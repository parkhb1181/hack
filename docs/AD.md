# 광고 소재

인스타그램용 캐러셀 5장과 15초 릴스 녹화 가이드.

**원칙 하나: 화면에 나오는 숫자는 전부 실제 출력이다.** 카피는 지어내도 되지만
결과 화면의 값은 손으로 적지 않는다. 발표에서 "이 숫자 어디서 나온 거냐"는
질문이 반드시 나오고, 거기서 막히면 나머지가 다 흔들린다.

---

## 1. 캐러셀 (권장)

파일: [`public/ad/carousel.html`](../public/ad/carousel.html)

```bash
npx next dev
```

열기: `http://localhost:3000/ad/carousel.html`

### PNG로 뽑기

1. 크롬에서 열고 F12
2. Elements 탭에서 `<div class="card ...">` 를 우클릭
3. **Capture node screenshot** (노드 스크린샷 캡처)
4. 1080×1350 PNG가 그대로 저장된다. 다섯 장 반복.

카드 위에 붙은 회색 라벨(`1 / 5 · 훅`)은 `.card` 바깥이라 캡처에 안 들어간다.

### 규격 근거

- **1080×1350 (4:5).** Meta가 1:1보다 4:5를 권장한다. 모바일에서 화면을 3분의 1
  더 차지하고 도달·참여가 더 좋다.
- **캐러셀은 카드 크기가 전부 같아야 한다.** 한 장만 비율이 달라도 잘린다.
- 카드 2장~10장. 이미지 최대 30MB.

### 다섯 장 구성

| # | 역할 | 핵심 |
| --- | --- | --- |
| 1 | 훅 | `나만 좋아하는 걸까?` — 질문형. 스크롤을 멈추는 카드 |
| 2 | 문제 | `근데 친구는 네 카톡을 안 봤잖아` — 왜 감이 아니라 계산인지 |
| 3 | 결과 | 실제 결과 화면. **가장 중요한 카드** |
| 4 | 근거 | 지표 6종 그리드 — 감이 아니라는 증거 |
| 5 | 신뢰 | 프라이버시 + CTA |

**5번을 빼지 마라.** 카톡을 올리라는 앱에서 사람들이 제일 먼저 하는 질문이고,
OCR·임베딩이 로컬이라 실제로 답할 수 있는 몇 안 되는 자리다.

### 3번 카드의 값이 어디서 왔나

`public/demo_hot.txt`를 앱에 넣어 나온 실제 출력이다.

```
고백 성공 확률 78%
반응 오는데요? 조금만 더
상대가 훨씬 많이 보내고 먼저 말을 걸어.     ← LLM 한 줄, 실제 응답
메시지 120개 · 4개 축 중 4개로 산출
```

이 파일은 `fixtures/seeds/seed_onesided.pc.txt`의 **발화자를 뒤집은 것**이다.
우리 시드는 전부 "내가 더 다가가는" 쪽이라 퍼센트가 30%대에서만 나온다.
뒤집으면 상대가 다가오는 대화가 되고 78%가 된다.

케이스를 다시 고르고 싶으면:

```bash
npx tsx scripts/dev/adcase.ts
```

시드마다 기울기와 퍼센트를 뽑고, 뒤집은 판(`↔`)도 같이 낸다.

**78%가 우리 합성 데이터의 천장이다.** 80을 넘겨야 `이건 뭐, 끝났죠` 문구가
나오는데, 내 쪽 발화를 솎아 더 기울여 봐도 75~80.7 사이에서 맴돈다 —
동조 축(임베딩)이 기울기를 0 쪽으로 당기기 때문이다. 진짜로 80을 넘기려면
실제로 그만큼 일방적인 대화가 필요하다.

## 2. 15초 릴스 (여유 있으면)

**편집하지 마라.** 무편집 화면 녹화가 정답이다. 자막이나 음악을 붙이는 순간
비용이 10배가 되고, 앱 자체가 이미 3막 구조를 갖고 있다.

규격: **1080×1920 (9:16)**, MP4 / H.264.

### 찍기 전 체크리스트

앱이 그 순간 완벽하게 돌아야 한다. 하나라도 죽어 있으면 화면에 폴백이 뜬다.

```bash
# OCR 서버 (캡처를 쓸 때만)
.venv-paddle/Scripts/python.exe -m uvicorn ocr_service.main:app --port 8756

# 임베딩
ollama serve

# LLM 한도 — 여기서 429가 나면 한 줄이 폴백으로 떨어진다
npx tsx scripts/check/quota.ts
```

리허설을 **반드시 한 번** 돌려라. Gemini 한도가 차 있으면 결과 한 줄이
폴백 문장으로 바뀐다. 폴백도 말은 되지만 매번 같은 문장이라 티가 난다.

### 스토리보드 (15초)

| 초 | 화면 | 노리는 것 |
| --- | --- | --- |
| 0–2 | 인트로 → `시작하기` | 뭐 하는 앱인지 |
| 2–4 | 파일 올리기, 썸네일 3개가 뜸 | "이것만 하면 되네" |
| 4–9 | **처리 화면** — 단계가 하나씩 차고 한마디가 굴러감 | 여기가 제일 볼거리다 |
| 9–13 | 결과 78% + 한 줄 | 결정타 |
| 13–15 | 지표 화면 살짝 스크롤 | "근거도 있네" |

처리 화면의 회전 문구(`같은 말 몇 번 했는지도 보고 있어요. 네, 그것도요.`)는
기다리는 시간을 채우려고 넣은 건데, 영상에서는 이게 유일한 "말하는" 구간이다.
너무 빨리 지나가면 안 보이므로 **캡처로 찍는 편이 낫다** — txt는 파싱이 순식간에
끝나서 처리 화면이 스쳐 지나간다.

### 창 크기

앱은 `max-width: 420px`인 폰 레이아웃이다.

1. 크롬 F12 → 디바이스 툴바(Ctrl+Shift+M)
2. 해상도 **540 × 960** 직접 입력
3. DPR 2로 녹화하면 1080×1920이 그대로 나온다

녹화는 OBS나 Xbox Game Bar(Win+G)로 창 영역만 잡는다. 커서 표시는 끄는 게 좋다.

### ⚠️ 실제 캡처를 쓰지 마라

`public/mom_01.png` 같은 테스트용 캡처는 **실제 대화 내용이 그대로 화면에 찍힌다.**
업로드 화면에서 썸네일로 한 번, 개발자 모드에서 또 한 번 노출된다.
영상에는 데모용으로 만든 것만 쓴다.

### 흔한 실패

- **Gemini 429** → 한 줄이 폴백으로 바뀐다. 리허설로 미리 확인
- **처리 화면이 순식간에 지나감** → txt 대신 캡처로 찍는다
- **커서가 화면 중앙에서 어른거림** → 클릭 후 창 밖으로 빼둔다
- **결과가 하드 플로어로 떨어짐** → 메시지가 모자란 파일이다. `demo_hot.txt`를 쓴다

## 3. 캐러셀 첫 카드에 영상 넣기

인스타 캐러셀은 영상 카드를 섞을 수 있다. 녹화가 잘 나오면 1번 카드를 영상으로
바꾸고 이미지 카드는 4장만 쓰는 구성도 된다. 이때도 **비율은 전부 4:5로 맞춰야
한다** — 영상만 9:16이면 잘린다.
